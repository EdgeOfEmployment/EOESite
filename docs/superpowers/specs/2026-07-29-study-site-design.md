# 취업 준비 스터디 사이트 설계

## 개요

취업 준비 스터디(5~15명 규모)를 위한 웹사이트. 회원가입은 관리자 승인을 거쳐야 하며, 스터디의 4가지 핵심 활동(기상/스터디/목표달성 인증, 코딩테스트 스터디, 자소서 피드백 및 회사분석, 모의면접)을 각각 별도 게시판으로 지원한다.

## 기술 스택

- **Next.js** (App Router), **Vercel** 배포
- **Supabase**: Postgres(DB) + Auth(이메일/비밀번호) + Storage(인증 사진 업로드)
- Row Level Security로 "승인된 사용자만 접근 가능" 규칙을 DB 레벨에서 강제

## 사용자 및 권한 모델

- `status`: `pending`(가입 대기) / `approved`(승인됨) / `rejected`(거부/강퇴)
- `role`: `member` / `admin`
- 요청자 본인이 유일한 관리자
- 인증되지 않은 사용자: 로그인/회원가입 페이지만 접근 가능
- `pending` 사용자: 로그인은 가능하나 "승인 대기 중" 안내 페이지만 노출
- `approved` 사용자만 실제 서비스 페이지 접근 가능

## 데이터 모델

- `users` — Supabase Auth 연동 프로필: 이름, email, role, status
- `checkin_posts` — 기상/스터디/목표달성 인증: 작성자, 날짜, 타입(기상/스터디/목표달성), 사진, 텍스트
- `checkin_comments` — checkin_posts에 대한 댓글
- `checkin_reactions` — checkin_posts에 대한 이모지 반응
- `coding_problems` — 코테 문제: 문제명, 링크, 대상 주차, 등록자(관리자)
- `coding_checks` — (coding_problems × user) 본인 풀이 완료 여부
- `job_posts` — 1일1공고 인증: 작성자, 날짜, 회사명, 공고 링크/정보, 자소서 원문, 피드백요청 여부
- `job_post_reactions` — job_posts에 대한 이모지 반응 (댓글 없음)
- `feedback_docs` — job_posts에서 피드백 요청 시 생성되는 자소서 스냅샷 (줄/단락 배열)
- `feedback_comments` — (feedback_docs × 줄번호) 줄 단위 댓글 스레드
- `interview_events` — 모의면접 공지: 작성자, 일시, 장소/방식, 설명
- `interview_rsvps` — interview_events에 대한 참석 신청자 목록

## 페이지 구성

### 인증
- `/signup` — 이름/이메일/비밀번호 입력, 가입 시 status=pending
- `/login` — 이메일/비밀번호 로그인
- `/pending` — status가 pending인 사용자에게 노출되는 승인 대기 안내 페이지

### 관리자 (`/admin`, role=admin만 접근)
- 가입 대기자 목록 → 승인/거부
- 전체 멤버 목록 → 강퇴(status를 rejected로 변경)
- 4개 게시판의 게시글 삭제(부적절한 글 관리)

### 대시보드 (`/`)
- 4개 보드로 가는 네비게이션
- 오늘의 현황판: 내가 아직 하지 않은 인증 항목 표시 + 멤버별(행) × 인증종류별(열) 오늘 완료 여부 표

### 인증 게시판 (`/checkin`)
- 기상/스터디/목표달성 3종 태그를 하나의 피드에서 구분 표시
- 글쓰기: 사진 업로드 + 텍스트 + 인증 종류 선택
- 각 글에 댓글 + 이모지 반응
- `/checkin/calendar` — 월별 달력에서 날짜별 또는 멤버별로 인증 현황 확인

### 코테 스터디 (`/coding`)
- 관리자만 문제 등록: 문제명, 링크, 대상 주차(화요일 기준)
- 문제별로 멤버 목록이 나열되고, 각 멤버는 본인 항목만 체크 가능(자가 체크 — 스터디 공용 GitHub 저장소에 본인이 올린 것을 스스로 확인 후 체크)
- 지난 주차 문제는 히스토리로 누적

### 자소서 피드백 + 회사분석 (`/jobposts`, `/feedback/[id]`)
- `/jobposts` — 1일1공고 인증 게시판: 회사명, 공고 정보, 자소서 원문, 날짜 작성. 이모지 반응만 가능(댓글 없음)
- 작성자가 "피드백 받고 싶어요" 체크 시 `feedback_docs`에 자소서 스냅샷 생성
- `/jobposts/calendar` — 날짜별로 누가 어떤 공고에 지원했는지 확인
- `/feedback/[id]` — 스냅샷을 줄/단락 단위로 표시, 각 줄에 "댓글 추가" 버튼으로 줄 단위 댓글 스레드 작성 (GitHub PR 리뷰 스타일이되 diff 없이 고정된 줄 기준). 원본 job_post는 수정되지 않음

### 모의면접 (`/interviews`)
- 면접이 잡힌 멤버가 공지 글 작성: 일시, 장소/방식, 설명
- 다른 멤버는 "참석하기" 버튼으로 참석 신청, 신청자 목록이 공지 글에 표시
- 지난 공지는 히스토리로 누적

## 제외 범위 (Non-goals)

- GitHub API를 통한 자동 풀이 확인 (수동 자가 체크로 대체)
- 실시간 알림/푸시 알림
- 모바일 네이티브 앱 (반응형 웹으로만 대응)
- 통계/랭킹/연속 출석일수 등 게이미피케이션 요소

## 테스트 전략

- 핵심 권한 로직(승인 전 접근 차단, 관리자 전용 페이지, 코테 체크는 본인만 가능) 단위/통합 테스트
- 회원가입 → 승인 → 로그인 플로우 e2e 테스트
- 피드백 줄단위 댓글 생성/조회 로직 단위 테스트
